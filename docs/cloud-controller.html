Gerenciamento centralizado estilo UniFi via WebSocket reverso — sem IP público nem VPN no roteador.

1. Arquitetura do Cloud Controller (cloudController/)

O servidor assíncrono em PHP (server.php) mantém conexões WebSocket persistentes com a frota de roteadores (/ws/router) e com o dashboard dos administradores (/ws/admin):

  • Adoção e Telemetria: Roteadores conectam ao controlador e reportam clientes conectados, tráfego, uptime e status dos perfis QoS.
  • Túnel Reverso WebUI: Permite abrir a interface LuCI/WebUI original do roteador (porta 80 local) diretamente pelo navegador na nuvem via mensagens tcp_tunnel_open, tcp_tunnel_data e tcp_tunnel_close.
  • Terminal Remoto Web (xterm.js): Console interativo em /ws/terminal?mac=... usando frames binários WebSocket e FIFOs locais no roteador.
  • Bloqueio DNS Centralizado: Gerenciamento de listas de bloqueio DNS globais e por dispositivo.

2. Autenticação e Controle de Acesso (RBAC)

O painel conta com autenticação local (senhas com hash bcrypt em users.json e sessão assinada via cookie fl_session com HMAC-SHA256):

PerfilPermissões
viewerVisualização de roteadores, telemetria e status no dashboard.
operatorAdoção, renomeação, perfis QoS, bloqueio DNS, reboot, terminal remoto e túnel WebUI.
adminTodas as permissões de operator + esquecer roteador e gerenciamento completo de usuários.
🔐No primeiro acesso (quando ainda não há usuários cadastrados), o /dashboard solicita o código de setup impresso nos logs do servidor para criar o primeiro administrador.

3. Portal Cativo, QoS e Persistência (captivePortal/)

  • Perfis de Banda (QoS): Quatro perfis pré-configurados (visitante, basico, premium, ilimitado) gerenciados via WebUI local ou pelo Cloud Controller.
  • Persistência Resiliente a Factory Reset: O serviço /etc/init.d/floresta_agent sincroniza e restaura automaticamente as configurações a partir das partições /data/etc/config e /user_data1/etc/config caso o roteador sofra reset.

Apontando um Roteador para o seu Controlador

set-inform https://<SEU_CONTROLADOR>/ws/router
# ou via UCI:
uci set floresta_cloud.global.server_url="https://<SEU_CONTROLADOR>/ws/router"
uci commit floresta_cloud
/etc/init.d/floresta_agent restart

4. Deploy no Google Cloud Run

O controlador foi desenhado para rodar em instância única com volume persistente (Cloud Storage FUSE montado em /app/data):

# Deploy automatizado via PowerShell:
.\deploy_cloud_run.ps1
