Redundância de slots A/B na Flash SPI-NAND de 128 MB do Broadcom BCM6764.

A plataforma Broadcom BCA utiliza dois bancos lógicos independentes (Slot 1 e Slot 2) controlados pelas partições metadata1 e metadata2 para garantir tolerância a falhas.

1. Visão Geral da Arquitetura Dual-Bank

  • Slot 1 (Bank A — Primário): Contém bootfs1 (Kernel Linux FIT) e rootfs1 (SquashFS).
  • Slot 2 (Bank B — Backup): Contém bootfs2 (Kernel Linux FIT) e rootfs2 (SquashFS).
  • Metadados (metadata1 / metadata2): Armazenam committed-img (1 ou 2), valid-imgs e número de sequência incremental.

2. Mapeamento Completo de Partições (/proc/mtd)

dev:    size   erasesize  name
mtd0: 08000000 00020000 "spi1.0"      -> Flash NAND SPI inteira (128 MB)
mtd1: 00200000 00020000 "loader"      -> Bootloader U-Boot + TPL (2 MB)
mtd2: 07280000 00020000 "image"       -> Contêiner UBI principal (~114.5 MB)
mtd3: 00380000 00020000 "tpconfig"    -> NVRAM de fábrica tp_data (PIN, MAC, Calibração)
mtd4: 00700000 00020000 "userconfig"  -> Configurações persistentes do usuário
mtd5: 00000110 0001f000 "metadata1"   -> Metadados de boot do Slot 1
mtd6: 00000110 0001f000 "metadata2"   -> Metadados de boot do Slot 2
mtd7: 006e4780 0001f000 "bootfs1"     -> Kernel + DTBs do Slot 1 (~6.9 MB)
mtd8: 01aa4000 0001f000 "rootfs1"     -> RootFS SquashFS do Slot 1 (limite 33.1 MB)
mtd9: 006e4780 0001f000 "bootfs2"     -> Kernel + DTBs do Slot 2 (~6.9 MB)
mtd10: 01ac3000 0001f000 "rootfs2"    -> RootFS SquashFS do Slot 2 (limite 33.1 MB)
mtd11: 0020f000 0001f000 "data"       -> Partição persistente /data (UBIFS)
mtd12: 00117000 0001f000 "defaults"   -> Padrões de fábrica
mtd13: 0026c000 0001f000 "tp_data"    -> Dados adicionais de calibração
mtd14: 002e8000 0001f000 "user_data1" -> Dados do usuário no Slot 1
mtd15: 002e8000 0001f000 "user_data2" -> Dados do usuário no Slot 2

3. Como Espelhar o Firmware no Slot 2 (rootfs2)

O Rescue Mode grava apenas o Slot 1 (bootfs1 e rootfs1). Para espelhar a mesma imagem no Slot 2:

Método A: Pelo Linux Ativo via SSH

# 1. No PC, envie a imagem para /tmp:
scp -O rootfs1_mod.bin root@192.168.0.1:/tmp/

# 2. No roteador via SSH, identifique o volume UBI do rootfs2:
for v in /sys/class/ubi/ubi0_*; do
    [ -f "$v/name" ] && echo "$v -> $(cat "$v/name")"
done

# 3. Grave no dispositivo correspondente ao rootfs2 (ex: /dev/ubi0_3):
ubiupdatevol /dev/ubi0_3 /tmp/rootfs1_mod.bin
ubinfo /dev/ubi0_3
rm -f /tmp/rootfs1_mod.bin && sync

Método B: Pelo U-Boot via TFTP (Serial UART)

setenv ipaddr 192.168.12.1; setenv serverip 192.168.12.2; setenv netmask 255.255.255.0
ubi part image
tftpboot 0x05000000 rootfs1_mod.bin
ubi write 0x05000000 rootfs1 <TAMANHO_HEX>
ubi write 0x05000000 rootfs2 <TAMANHO_HEX>
setenv bootcmd "test_mode enable; sdk boot_img"
saveenv; reset

4. Como Alternar o Slot Ativo de Boot no U-Boot

# Forçar Boot pelo Slot 1:
setenv boot_image 1; setenv committed_image 1; saveenv; reset

# Forçar Boot pelo Slot 2:
setenv boot_image 2; setenv committed_image 2; saveenv; reset
✅Se o slot selecionado falhar na verificação de integridade, o watchdog do U-Boot alterna automaticamente de volta para o slot íntegro.
