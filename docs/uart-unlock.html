Engenharia reversa do bloqueio serial, flag secreta do Dropbear (-L) e correção do PTY.

1. Conexão Serial USB-TTL e Desbloqueio no U-Boot

  • Parâmetros: 115200 8N1, Flow Control OFF (console ttyAMA0 — ARM PrimeCell PL011).
  • Pinagem: TX → RX, RX → TX, GND → GND (nunca conecte o pino VCC).

Por padrão, o U-Boot passa test_mode=disable ao kernel e os módulos user-debug / kmonitor bloqueiam o RX da serial. Para desbloquear no prompt => do U-Boot:

test_mode enable
sdk boot_img

Para tornar permanente no ambiente do U-Boot:

setenv bootcmd "test_mode enable; sdk boot_img"
saveenv

2. Backup Completo de 128 MB (SPI-NAND mtd0)

Antes de qualquer alteração, extraia os 128 MB (134.217.728 bytes) da flash via socket TCP no PowerShell (PC em 192.168.12.2):

# No Windows (PowerShell):
$listener = New-Object System.Net.Sockets.TcpListener ([System.Net.IPAddress]::Any, 8080)
$listener.Start()
$client = $listener.AcceptTcpClient()
$stream = $client.GetStream()
$file = [System.IO.File]::Create("$HOME\Downloads\archer_be220_full_dump.bin")
$stream.CopyTo($file)
$file.Close(); $client.Close(); $listener.Stop()
# No roteador:
cat /dev/mtd0 | nc 192.168.12.2 8080

3. As 4 Armadilhas Proprietárias Descobertas no RootFS

3.1 Hash da senha exigido também em /etc/passwd

O binário do Dropbear da TP-Link lê o hash diretamente de /etc/passwd. Se contiver root:x:..., a autenticação falha com User account 'root' is locked. O hash MD5-crypt deve estar tanto em /etc/shadow quanto em /etc/passwd.

3.2 O Boot Hook Real: /etc/rc.d/S99zzzzboot_done

A TP-Link removeu /etc/init.d/done, logo /etc/rc.local nunca é executado. O único script final chamado pelo rcS no término do boot é /etc/rc.d/S99zzzzboot_done.

3.3 A Flag Secreta do Dropbear (-L)

A TP-Link alterou o código C do Dropbear (svr-runopts.c e svr-chansession.c) adicionando a trava svr_opts.sessionEnable == 0. Sem a flag -L, o Dropbear aceita a senha mas rejeita silenciosamente qualquer pedido de pty-req, shell ou exec:

/usr/sbin/dropbear -p 22 -L -B &

3.4 Pseudoterminal (/dev/ptmx e devpts)

O kernel monta /dev/pts com ptmxmode=000 e /dev/ptmx é um nó estático inoperante. No boot (S99zzzzboot_done), remontamos com permissão 666 e recriamos o link simbólico:

mkdir -p /var/dropbear /dev/pts
rm -f /var/dropbear/fail_count
mount -o remount,mode=666,ptmxmode=666 /dev/pts 2>/dev/null || true
rm -f /dev/ptmx
ln -sf pts/ptmx /dev/ptmx
chmod 666 /dev/pts/ptmx /dev/ptmx 2>/dev/null || true
/usr/sbin/dropbear -p 22 -L -B &
⚠️Importante: Nunca faça symlink de /var/dropbear/fail_count para /dev/null (o fscanf() entra em loop infinito). Use apenas rm -f /var/dropbear/fail_count.

4. Reconstrução Automatizada com build_rootfs.sh

⚠️NTFS vs ext4: Extrair o SquashFS em uma partição Windows NTFS (/mnt/f/...) descarta os 459 symlinks do Linux e causa Kernel panic: Requested init /etc/preinit failed (error -2). O script build_rootfs.sh faz toda a extração em /tmp/be220_squashfs_work (ext4 nativo do WSL2).
# Build padrão no WSL2 (SquashFS XZ, block size 1 MB):
wsl -d Ubuntu-24.04 bash build_rootfs.sh
