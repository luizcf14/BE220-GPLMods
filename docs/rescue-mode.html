Recuperação ("unbrick") nativa pelo navegador sem abrir o gabinete ou soldar UART.

O U-Boot da Broadcom (bcmbca) implementa um mini servidor HTTP embutido (httpd.c / bcmbca_net.c) na porta 80 quando o botão WPS é mantido pressionado durante a energização.

1. Fluxo da Arquitetura de Recuperação

[Usuário] Segura botão WPS e liga a fonte (20s)
   │
   ▼
[U-Boot] Dispara flag 'firmware_recovery=1' e inicia pilha uIP (192.168.0.1:80)
   │
   ▼
[Navegador] Envia pacote via HTTP POST (recovery_bundle.bin)
   │
   ▼
[nm_tpFirmwareCheck] Valida tamanho, MD5 com salt TP-Link e partição support-list
   │
   ▼
[flash_upgrade_img_bundle] Valida hashes SHA256 + string compatible no FIT
   │
   ▼
[NAND Flash] Grava loader (mtd1), bootfs1 (mtd7) e rootfs1 (mtd8) e reinicia

2. Como Entrar no Rescue Mode

⚠️A placa de rede do computador deve ter IP estático 192.168.0.2. O servidor HTTP do U-Boot não possui serviço DHCP.
  1. Configure o IP estático no PC
    IP 192.168.0.2, máscara 255.255.255.0, gateway 192.168.0.1. Conecte o cabo na porta LAN 1.
  2. Desligue o roteador da tomada.
  3. Segure o botão WPS e ligue a energia mantendo-o pressionado continuamente por 20 segundos.
  4. Solte o botão WPS e abra http://192.168.0.1 no navegador.
  5. Envie o recovery_bundle.bin clicando em Browse → Upgrade e aguarde o reboot automático (3 a 5 minutos).

3. Estrutura do Pacote (Cabeçalho TP-Link + Broadcom FIT)

Ao receber o upload na tela de Rescue Mode (http_update_image), o U-Boot executa duas etapas sequenciais de validação:

Etapa 3.1: Cabeçalho Externo TP-Link (nm_tpFirmwareCheck)

OffsetTamanhoCampoDescrição
0x00004 bytestotal_lenTamanho total do arquivo (Big-Endian uint32_t). Deve ser <= upload_len.
0x000416 bytesmd5_digestHash MD5 sobre tp_salt (16B) + bytes[0x0014..total_len] com salt 7a2b15ed9b98596de504ab44ac2a9f4e.
0x00140x1000 Bfw_headerZerado (0x00) para acionar o fluxo "Firmware process common." sem criptografia RSA/AES.
0x1014Variávelfwup-ptnTabela contendo support-list (Archer BE220) e soft-version.
Após soft-versionRestanteFIT BundleInício exato do pacote FIT Broadcom (0xd00dfeed).
🚨Por que um FIT puro falha no Rescue Mode: Se o arquivo começar direto com 0xd00dfeed sem o cabeçalho 0x1014 + fwup-ptn, a função nm_tpFirmwareCheck recusa o upload. O script generate_recovery_bundle.sh já constrói o cabeçalho completo em recovery_bundle.bin.

Etapa 3.2: Pacote Interno Broadcom FIT (flash_upgrade_img_bundle)

ComponenteNó no .itsDestino MTDDescrição
loaderloader_6764mtd1 (loader)Bootloader U-Boot/TPL
bootfsbootfs_6764mtd7 (bootfs1)Kernel Linux FIT + DTBs (Slot 1)
rootfsrootfs_6764mtd8 (rootfs1)Sistema de arquivos SquashFS (Slot 1)

O nó de configuração exige a string de compatibilidade exata:

compatible = "flash=nand;chip=6764;fstype=squashfs";
ℹ️O Rescue Mode grava exclusivamente no Slot 1 (bootfs1 e rootfs1), preservando o Slot 2 intacto como fallback. Veja o Guia Dual-Bank.

4. Como Gerar o Pacote no WSL2

wsl -d Ubuntu-24.04 bash generate_recovery_bundle.sh
  • recovery_bundle.bin — Com cabeçalho TP-Link + FIT (para Rescue Mode Web UI).
  • recovery_bundle_raw_fit.bin — Pacote FIT puro (para uso com /sbin/bcm_flasher via SSH).

5. Engenharia Reversa de Firmwares Oficiais (fw-type:Cloud)

Firmwares oficiais assinados da TP-Link (ex: ver1-1-7-P1..._2048_signed.bin) usam um envelope híbrido RSA-2048 PSS + AES-128-CBC (nm_decryptFwData):

  • Chave Pública RSA-2048: Embutida em /usr/bin/nvrammanager (offset 0x19240, 451 bytes PEM) e no U-Boot.
  • Bloco RSA-PSS (0x0130..0x0230): Elevando os 256 bytes ao expoente público (e = 65537 mod n), obtém-se um bloco EM codificado com PKCS#1 v2.1 EMSA-PSS (SHA-256, MGF1, salt de 32 bytes).
  • Extração de Chave AES e IV: Após aplicar XOR da máscara MGF1-SHA256(H, 223) sobre maskedDB, os últimos 32 bytes do DB (o salt PSS) contêm os 16 bytes da chave AES-128 seguidos pelos 16 bytes do IV.
  • Payload (0x0230..fim): Descriptografado com AES-128-CBC, revelando o fwup-ptn em 0x1014 e o FIT Broadcom (0xd00dfeed) logo após soft-version.
